Why CmdQ

Does it help you get more done? Yes. Claude Code users keep running into three problems. CmdQ was built to remove them.

① Time lost to usage limits

Before
When you hit the 5-hour or weekly limit, the work stops. You wait for the reset and type the command again.
With CmdQ
The stopped task stays in Waiting for reset and continues in the same session after the reset. Work moves forward while you're away.

② Keeping several projects in order

Before
You keep a window open for each project and switch between them to see what has finished.
With CmdQ
Different paths run at the same time, and tasks in the same path run in order. Link a follow-up task as a chain, and a flow like build → summarize the logs keeps going without you.

③ To-dos that live only in your head

Before
You remember a command or jot it down, then type it in later.
With CmdQ
Park it in To Do right away. When it's ready, promote it to the Auto queue.

Get started in 3 minutes

Already have the Claude Code CLI? Skip to step 2.

1

Install the Claude Code CLI

Install it with one of the first three commands. If the last command prints a version number, you're ready.

curl -fsSL https://claude.ai/install.sh | bash
brew install --cask claude-code
npm install -g @anthropic-ai/claude-code
claude --version
2

Install CmdQ and open it

Download the DMG, move CmdQ to your Applications folder, and open it. If CmdQ can't find the CLI, it shows install instructions first. Once the CLI is installed, click Check again to continue.

Queued tasks run Claude Code with --dangerously-skip-permissions. Claude Code will read, write, and delete files and run commands in the target folder without asking you first. Review what you queue, keep your work under version control, and use this app only on folders you are willing to let it change. You are responsible for the results of the tasks you run.

This notice appears the first time you open CmdQ. The queue and terminals stay off until you click Agree and start.

3

Add your first task

Click + Folder to open a project tab, then type a command. In the command box, Enter adds it to To Do and ⌘Enter adds it to the auto queue. Wherever the focus is, pressing / moves focus to the command box. A pasted image shows up as [IMAGE], and CmdQ passes it along when the command runs.

Type a word that starts with / in the command box to see your skills. Pick one with ↑ ↓ and insert it with Tab. If you press Enter while the list is open, the command is added as typed, without the skill.

Three core ideas

① Two queues

Auto queue

Runs items from the top down. In the same path, the next item starts only after the one ahead of it finishes. Different paths run at the same time, up to three by default.

To Do

A list for holding and reviewing work. Items here never run on their own.

▲ Promote  /  ▼ Move to To Do: move items between the two queues at any time

② Three kinds of target

Path

Starts a new session in the project folder you choose.

Session

Continues an existing Claude session, so the earlier conversation stays in context.

Interactive

Skips the queue and opens an interactive terminal in the current tab's folder, where you talk to Claude directly.

③ Chains

Drag an item under another item to make a chain. When the parent finishes, the child runs in the parent's session. If the parent fails, the child doesn't run. Open the failed parent in an interactive terminal and send one message. The parent turns Done, and the waiting child runs next. If a child fails, the children after it wait. Re-run the failed child and the chain picks up again.

Usage

The header bars show 5-hour window and Weekly limit usage, and the ring shows 5-hour usage. Next reset beside them shows the time left until the next reset. The menu bar icon shows the same values. If you hit the weekly limit, Weekly limit · resumes appears, and the queue starts again when the weekly limit resets.

On first launch, CmdQ asks once whether to connect the Claude Code statusline. Choose Connect to read usage from the statusline faster. Your existing statusline display stays as it is. Choose Later to rely on /usage checks only. CmdQ won't ask again, and Settings has no option to connect later.

Project tabs and item numbers

A tab shows only the items for its path. Turn on Show all to see the items from every open tab, grouped by path. When you switch tabs, the add form goes back to the Path target and the To Do queue.

Closing a tab doesn't delete its items, and auto queue items for that path keep running.

A number such as #12 is the item's unique ID. Notifications use the same number to point to an item.

Menu bar

Click the icon to see usage, the time until the reset, and the auto queue status. The menu includes Open window, Report a bug, and Quit. Report a bug opens a new GitHub issue in your browser, and you decide whether to submit it.

Closing the window doesn't quit CmdQ: it stays in the menu bar and keeps running the auto queue. To stop it completely, choose Quit.

Dots on the icon

  • Red dot, top right: unread notifications
  • Yellow dot, bottom right: an item is waiting for the reset
  • Green dot, bottom right: an item or an interactive terminal is running

Controls

Drag to reorder or nest

  1. Drag a Queued or Waiting for reset item up or down to change the run order.
  2. Move it to the right while dragging to make it a child (chain) of the item above. Both items must target a path, and chains go one level deep.
  3. Dragging is locked while Show all is on. Pick a single tab to drag again.

Attaching reference material

Attach the files, links, and notes a command is based on. Attachments belong to a session, and every command in that session shares them.

  1. Attach: use the File, Link, or Memo button in the add bar or the 📎 button on a card (it opens the drawer). You can also drag files from Finder onto the window. Child commands use the parent card's 📎. The 📎 in bookmarks and terminals opens and adds to the same session's attachments, even after the card is deleted and even when there are none yet.
  2. Use in a command: put [첨부] in a command to pass all of the session's attachments to claude when it runs, or [첨부:3] to pass only that one. Without a marker, no attachments are passed.
  3. Pick from a list: type # in the command box to open All attachments, Session attachments, and Command attachments. Select several with Space and press Tab to insert their markers. Type @ to insert a file or folder path.
  4. View: in the drawer, read text as Markdown or Raw text and preview images and PDFs. Web links open with your signed-in session. For a link that needs a sign-in, use Save text so claude gets the saved copy.
A session holds up to 10 attachments. Each file can be up to 20 MB by default. For a larger file, use Change in settings to raise the limit. Text over 2 MB isn't previewed, and you get Show file location instead. Attachments are copies the app makes. They are deleted once no command, bookmark, or running terminal uses the session, and your original files stay where they are. If deleting a bookmark would delete attachments too, the app asks first and tells you how many. An expanded command is capped at 120 KB and memos at 64 KB per command, and a resumed run doesn't get the attachment list again. You can't open Interactive from the add bar while it has attachments or attachment markers, because markers aren't expanded there.

Interactive terminal and history

When a task needs back-and-forth instead of the queue, work in the app's terminal.

Opening a terminal and running it in the background

  • Click ⌘ (Run interactively) on a card to open that item's terminal.
  • Choose Interactive as the add bar target to open a new claude terminal without a queue card. What you typed becomes the first message.
  • Choose Session, then click ▶ Terminal next to 🕐 History to attach to that session directly.
  • If the auto queue is running that session, a confirmation appears. Confirming stops the run and hands the session to the interactive terminal; the item is marked done with a Handed off badge. Cancelling changes nothing.
  • Click Run in background to keep the task going after you close the window. Click the Terminal running badge on the card to attach again.

Inside the terminal

  • When output stops, you get a Waiting for input notification (Interactive input-wait alert in Settings).
  • If you hit the usage limit, the terminal closes, and the queue item changes to Waiting for reset and continues after the reset.
  • Cmd+click a URL in the terminal to open it in your browser.
  • Click 📎 in the header to open the attachment dialog. Like the drawer, it lets you add, delete, reorder, edit memos, and drop files. Use Insert into terminal or Insert all to paste them into the input line. You press Enter yourself.
  • Click Snippets to open the Shared and This path command lists. Picking one fills the edit area, and Apply runs it.
  • If you use mod panels with claude, run claude with the fullscreen renderer to click them with the mouse: run /tui fullscreen in claude, or start it with the CLAUDE_CODE_NO_FLICKER=1 environment variable. With the default renderer, claude does not accept mouse input, so clicks do nothing (this is claude's behavior). To make the terminal wider, set Settings › General › Terminal window width to Full width.
  • Emoji (⬜, 📋, 🧩 and so on) are counted as two cells, as claude does, so tables and panels that mix in emoji stay aligned. Widening the window also adds terminal columns.
  • When you come back from another app or reopen a terminal, CmdQ has claude redraw the whole screen so the right-hand panel and text don't go blank. If the screen still goes blank, press ⇧⌘D to save a diagnostic file and attach it to an issue (it goes to diagnostics/ in the app data folder and contains terminal output, so review it before sharing).

Background terminal list

The N terminals button in the header (⇧⌘T) lists the live terminals so you can open or terminate them. Terminate all needs a second click. A terminal opened from the list goes back to the list with ⌃←.

Progress and session history

👁 shows a running item read-only. In Full session history, check the questions you want and save them with 🖼 Image or 📄 PDF. On a question screen, ← Back (⌃←) returns to the list.

Bookmarks

Click ☆ on a finished item's card to pin its session, and click ☆ in the header (⇧⌘B) to open the panel. A session you opened with Interactive or ▶ Terminal has no card, but you can still bookmark it with ☆ in the interactive terminal header or the background terminal list. Its alias is the first line of its first prompt (or the first 8 characters of the session ID if there is none), and its path is the folder it was first opened in. If the session is already bookmarked, ☆ is lit, and clicking it again removes the bookmark. If attachments would be deleted with it, the app asks first. In each row, ▶ opens an interactive terminal, 🕐 shows the session history, ✎ renames it, ✕ deletes it, and 📎 opens the attachment drawer. A bookmark stays even after you delete the original item, and so do the session's attachments, so you can keep opening and adding to them from 📎.

How the app works

To comply with Anthropic's third-party policy, this section describes how CmdQ works.

What the app does

  • Runs the official Claude Code CLI installed on your computer as a process
  • Queues tasks from several project paths and runs them in order or at a scheduled time
  • Shows progress in the menu bar and the app window
  • Checks for new versions. It only downloads release information and sends nothing

What the app doesn't do

  • Access credentials (OAuth tokens, API keys)
  • Store or send credentials
  • Send usage history or task content anywhere
  • Collect or analyze user data
All authentication, network traffic, and Claude calls are handled by the official Claude Code CLI. CmdQ only decides when and in what order to run that CLI.
