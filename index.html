왜 CmdQ인가

업무 효율에 도움이 되나요? 네. Claude Code를 쓰다 보면 세 가지 불편에 부딪힙니다. 이 앱은 그 불편 때문에 만들었습니다.

① 한도에 걸려 버리는 시간

기존 방식
5시간·주간 한도에 걸리면 작업이 멈춥니다. 리셋 시각을 기다렸다가 다시 입력해야 합니다.
CmdQ
멈춘 작업은 리셋 대기로 남았다가 리셋되면 그 세션에서 이어 실행됩니다. 자리를 비운 사이에도 작업이 진행됩니다.

② 여러 프로젝트의 순서 관리

기존 방식
프로젝트마다 창을 띄워 두고 오가며 끝났는지 지켜봐야 합니다.
CmdQ
경로가 다르면 동시에, 같은 경로는 순서대로 실행합니다. 체인으로 후속 작업을 이어 두면 빌드 → 로그 요약 같은 흐름이 손대지 않아도 이어집니다.

③ 머릿속에만 있는 할 일

기존 방식
떠오른 명령을 기억하거나 메모해 두었다가 나중에 직접 입력합니다.
CmdQ
일단 To Do에 쌓아 두고, 준비가 되면 자동 큐로 승격합니다.

3분 만에 시작하기

Claude Code CLI가 이미 있다면 2단계부터 보십시오.

1

Claude Code CLI 설치

아래 세 방법 가운데 하나로 설치합니다. 마지막 명령에서 버전이 나오면 준비가 끝난 것입니다.

curl -fsSL https://claude.ai/install.sh | bash
brew install --cask claude-code
npm install -g @anthropic-ai/claude-code
claude --version
2

CmdQ 설치 후 첫 실행

DMG를 내려받아 응용 프로그램 폴더로 옮긴 뒤 실행합니다. CLI를 찾지 못하면 설치 안내가 먼저 뜹니다. 설치를 마치고 다시 확인을 누르면 넘어갑니다.

큐에 넣은 작업은 Claude Code를 --dangerously-skip-permissions로 실행합니다. Claude Code가 대상 폴더에서 확인 없이 파일을 읽고, 쓰고, 지우며 명령을 실행합니다. 넣는 작업을 검토하고, 작업물은 버전 관리로 보호하고, 바뀌어도 되는 폴더에서만 사용해 주십시오. 실행한 작업의 결과는 사용자 책임입니다.

처음 실행하면 이 고지가 뜹니다. 동의하고 시작을 누르기 전에는 큐와 터미널이 실행되지 않습니다.

3

첫 작업 등록

+ 폴더로 프로젝트 탭을 열고 명령을 적습니다. 명령 입력창에서 Enter를 누르면 To Do에, ⌘Enter를 누르면 자동 큐에 들어갑니다. 다른 곳에 포커스가 있어도 /를 누르면 명령 입력창으로 바로 이동합니다. 이미지를 붙여 넣으면 [IMAGE]로 표시되고 실행할 때 함께 넘어갑니다.

입력창에서 /로 시작하는 단어를 치면 스킬 목록이 뜹니다. ↑ ↓로 골라 Tab으로 넣습니다. 목록이 떠 있을 때 Enter를 누르면 스킬은 들어가지 않고 적어 둔 명령이 그대로 등록됩니다.

핵심 개념 세 가지

① 두 개의 큐

자동 큐

위에서부터 차례로 실행합니다. 같은 경로는 앞 항목이 끝나야 다음이 시작하고, 경로가 다르면 기본 세 곳까지 동시에 진행합니다.

To Do

보관·검토용 목록입니다. 여기 있는 항목은 저절로 실행되지 않습니다.

▲ 승격  /  ▼ To Do로 이동 — 두 큐 사이는 언제든 옮길 수 있습니다

② 세 종류의 실행 대상

경로

지정한 프로젝트 폴더에서 새 세션으로 시작합니다.

세션

기존 Claude 세션을 이어서 실행합니다. 앞 대화의 맥락이 남습니다.

대화형

큐에 넣지 않고 지금 탭의 폴더에서 대화형 터미널을 바로 열어 Claude와 직접 주고받습니다.

③ 체인

항목을 다른 항목 아래로 끌어 넣으면 체인이 됩니다. 부모가 완료되면 하위 항목이 부모 세션을 이어받아 실행됩니다. 부모가 실패하면 하위는 실행되지 않습니다. 이때 실패한 부모를 대화형 터미널로 열어 한 번 입력하면 완료로 바뀌고, 기다리던 하위가 이어서 실행됩니다. 하위가 실패하면 그 뒤 하위는 멈춰 기다립니다. 실패한 하위를 재실행하면 다시 이어집니다.

화면 읽는 법

상태는 색과 라벨을 함께 표시합니다.

사용량

헤더 막대는 5시간 윈도우와 주간 한도 사용률, 링은 5시간 사용률입니다. 옆에 다음 리셋까지 남은 시간이 나옵니다. 메뉴 막대 아이콘에도 같은 값이 보입니다. 주간 한도에 걸리면 주간 한도 · 재개까지가 뜨고 주간 리셋 때 다시 실행됩니다.

첫 실행 때 Claude Code statusline 연결을 한 번 묻습니다. 연결을 고르면 statusline 값으로 사용량을 더 빨리 읽고, 원래 쓰던 statusline 표시는 그대로 남습니다. 나중에를 고르면 /usage 조회만 쓰고 다시 묻지 않습니다. 설정 화면에도 연결 메뉴는 없습니다.

프로젝트 탭과 작업 번호

탭은 그 경로의 항목만 보여 줍니다. 전체보기를 켜면 열어 둔 탭의 항목을 경로별로 묶어 봅니다. 탭을 바꾸면 추가 폼은 대상 경로, 넣을 곳 To Do로 돌아갑니다.

탭을 닫아도 그 경로의 항목은 지워지지 않고 자동 큐에서 계속 실행됩니다.

#12 같은 번호는 항목의 고유 번호입니다. 알림도 이 번호로 항목을 가리킵니다.

메뉴 막대

아이콘을 누르면 사용률·리셋까지 남은 시간·자동 큐 현황과 함께 창 열기·버그 제보·종료 같은 메뉴가 나옵니다. 버그 제보를 누르면 브라우저에 GitHub 새 이슈 화면이 열리고, 등록할지는 직접 정합니다.

창을 닫아도 앱은 메뉴 막대에 남아 자동 큐를 계속 실행합니다. 완전히 끄려면 종료를 누르십시오.

아이콘에 붙는 점

  • 오른쪽 위 빨간 점 — 확인하지 않은 알림
  • 오른쪽 아래 노란 점 — 리셋 대기 항목이 있음
  • 오른쪽 아래 초록 점 — 실행 중인 항목이나 대화형 터미널이 있음

조작하기

끌어서 순서 바꾸기 · 하위로 넣기

  1. 대기·리셋 대기 항목을 위아래로 끌면 실행 순서가 바뀝니다.
  2. 끄는 채로 오른쪽으로 옮기면 바로 위 항목의 하위(체인)가 됩니다. 둘 다 경로 대상이어야 하고, 하위는 한 단계까지만 둡니다.
  3. 전체보기가 켜져 있으면 끌기가 잠깁니다. 탭을 하나 고르면 풀립니다.

근거 자료 첨부하기

명령의 근거가 된 파일·링크·메모를 붙여 둡니다. 첨부는 세션에 묶여 같은 세션의 명령들이 함께 씁니다.

  1. 붙이기 — 추가바의 파일·링크·메모 버튼, 카드의 📎 버튼(드로어), 또는 Finder에서 창으로 끌어다 놓기. 하위 명령은 부모 카드의 📎를 씁니다. 즐겨찾기와 터미널의 📎에서도 같은 세션의 첨부를 열고 붙입니다. 이 📎는 카드를 지운 뒤에도, 첨부가 0개여도 보입니다.
  2. 명령에 넣기 — 명령에 [첨부]를 적으면 그 세션의 첨부 전체가, [첨부:3]을 적으면 그 첨부 하나가 실행 때 claude에게 전달됩니다. 마커가 없으면 첨부는 전달되지 않습니다.
  3. 골라 넣기 — 명령창에서 #을 치면 전체 첨부·세션 첨부·명령 첨부 목록이 뜹니다. Space로 여러 개 고르고 Tab을 누르면 마커가 들어갑니다. @를 치면 파일·폴더 경로를 넣습니다.
  4. 보기 — 드로어에서 텍스트는 마크다운/원문으로 보고 이미지·PDF는 바로 미리 봅니다. 웹 링크는 로그인한 상태 그대로 열립니다. 로그인이 필요한 링크는 본문 저장을 해 두면 claude에게 저장본이 넘어갑니다.
세션 하나에 첨부는 10개까지입니다. 파일 하나는 기본 20MB까지이고, 넘으면 설정에서 바꾸기로 상한을 올릴 수 있습니다. 2MB가 넘는 텍스트는 미리 보지 않고 파일 위치 열기를 보여 줍니다. 첨부는 앱이 따로 만든 복사본입니다. 그 세션을 쓰는 명령·즐겨찾기·실행 중인 터미널이 모두 사라지면 함께 지워지고 원본 파일은 그대로 남습니다. 즐겨찾기를 지울 때 첨부도 함께 지워지면 개수를 알려 주는 확인이 뜹니다. 펼친 명령은 120KB까지, 메모는 명령 하나에 64KB까지 들어가며 재개 실행에는 첨부 목록을 다시 넣지 않습니다. 추가바에 첨부나 첨부 마커가 있으면 대화형이 열리지 않습니다. 대화형은 마커를 펼치지 않기 때문입니다.

대화형 터미널과 기록

큐에 맡기기 애매해 직접 대화해야 하는 작업은 앱 안 터미널에서 합니다.

열기와 백그라운드

  • 카드의 ⌘(대화형 실행)로 그 항목의 터미널을 엽니다.
  • 추가바 대상에서 대화형을 누르면 큐 카드 없이 새 claude 터미널이 열리고, 적어 둔 글이 첫 질문이 됩니다.
  • 세션을 고른 뒤 🕐 히스토리 옆 ▶ 터미널을 누르면 그 세션에 바로 붙습니다.
  • 백그라운드로 계속을 누르면 창을 닫아도 작업이 이어집니다. 카드의 터미널 실행 중 배지를 누르면 다시 붙습니다.

터미널 안에서

  • 출력이 멎으면 입력 대기 알림이 뜹니다(설정의 대화형 입력 대기 알림).
  • 사용 한도에 걸리면 터미널이 닫히고, 큐 항목은 리셋 대기로 바뀌어 리셋 후 이어집니다.
  • 터미널의 주소는 Cmd+클릭으로 브라우저에서 엽니다.
  • 헤더의 📎로 첨부 다이얼로그를 엽니다. 드로어처럼 추가·삭제·순서 변경·메모 수정·끌어다 놓기가 되고, 터미널에 넣기·전체 넣기로 입력줄에 붙여 넣습니다. Enter는 직접 누릅니다.
  • 스니펫 버튼으로 공통·이 경로 명령 목록을 펼칩니다. 고르면 편집 영역이 채워지고 적용을 누르면 실행됩니다.
  • claude 에 mod 패널을 붙여 쓴다면, 패널을 마우스로 누르려면 claude 를 fullscreen 렌더러로 띄웁니다. claude 에서 /tui fullscreen 을 실행하거나 CLAUDE_CODE_NO_FLICKER=1 환경변수를 주고 실행하세요. 기본 렌더러의 claude 는 마우스 입력을 받지 않아 눌러도 반응하지 않습니다(claude 의 동작입니다). 터미널을 더 넓게 쓰려면 설정 › 일반 › 터미널 창 폭을 「전체 화면 폭」으로 바꾸세요.
  • 이모지(⬜·📋·🧩 등)를 claude 와 같이 2칸으로 세므로, 이모지가 섞인 표나 패널의 글자가 어긋나지 않습니다. 창을 넓히면 터미널 열 수도 함께 늘어납니다.

백그라운드 터미널 목록

헤더의 터미널 N개 버튼(⇧⌘T)으로 살아 있는 터미널을 보고 열거나 종료합니다. 전체 종료는 한 번 더 눌러야 실행됩니다. 목록에서 연 터미널은 ⌃←로 목록에 돌아옵니다.

진행 상황과 세션 이력

👁는 실행 중인 항목을 읽기 전용으로 보여 줍니다. 세션 전체 이력에서는 질문을 체크해 🖼 이미지 생성·📄 PDF 생성으로 저장합니다. 질문 화면에서는 ← 목록(⌃←)으로 돌아갑니다.

즐겨찾기

완료 항목 카드의 ☆로 세션을 고정하고, 헤더의 ☆(⇧⌘B)로 패널을 엽니다. 대화형이나 ▶ 터미널로 연 세션은 카드가 없어도 대화형 터미널 헤더나 백그라운드 터미널 목록의 ☆로 등록할 수 있습니다. 이때 별칭은 첫 질의의 첫 줄(없으면 세션 ID 앞 8자), 경로는 처음 연 폴더입니다. 이미 즐겨찾기인 세션은 ☆가 켜져 있고, 다시 누르면 해제됩니다. 함께 지워질 첨부가 있으면 먼저 묻습니다. 행의 ▶는 대화형 터미널, 🕐는 세션 이력, ✎는 별칭 바꾸기, ✕는 삭제, 📎는 첨부 드로어입니다. 원래 항목을 지워도 즐겨찾기는 남고, 그 세션의 첨부도 남아 📎로 계속 열고 붙일 수 있습니다.

앱 구조 공시

Anthropic 서드파티 정책 준수를 위해 이 앱의 작동 방식을 밝힙니다.

이 앱이 하는 일

  • 사용자 컴퓨터에 설치된 공식 Claude Code CLI를 프로세스로 실행
  • 여러 프로젝트 경로의 작업을 큐에 넣고 정해진 순서 · 예약 시각에 실행
  • 메뉴 막대와 창에서 진행 상황 표시
  • 새 버전이 있는지 확인 — 릴리스 정보만 내려받으며, 보내는 정보는 없습니다

이 앱이 하지 않는 일

  • 인증 정보(OAuth 토큰, API 키) 접근
  • 인증 정보 저장 또는 전송
  • 사용 기록·작업 내용의 외부 전송
  • 사용자 데이터 수집 또는 분석
모든 인증 · 네트워크 통신 · Claude 호출은 공식 Claude Code CLI가 담당합니다. CmdQ는 그 CLI를 언제 어떤 순서로 실행할지만 관리합니다.
