CmdQ ← 홈으로

개인정보 처리방침

CmdQ는 사용자 개인정보를 수집하지 않습니다.

수집하는 데이터

없습니다. CmdQ는 사용자 데이터를 CmdQ 제작자나 다른 외부로 전송하지 않습니다. 사용자가 켠 외부 연계의 결과 회신만 예외로, 사용자가 연결한 서비스로 갑니다(아래 「외부 연계(선택 기능)」).

메뉴에서 버그 제보나 기능 요청을 누르면 GitHub의 새 이슈 화면이 브라우저에서 열립니다. 이때 주소에는 앱 버전, macOS 버전, 아키텍처 세 가지만 담기고 경로나 큐 내용, 로그는 담기지 않습니다. 링크를 여는 순간 이 세 값이 주소에 담겨 GitHub으로 전달되고, 이슈로 등록할지는 GitHub 화면에서 직접 정합니다.

모든 작업 기록과 설정은 사용자 컴퓨터에만 저장됩니다.

저장 위치
~/Library/Application Support/com.doitasap.cmdq/
형식
SQLite 데이터베이스
외부 전송

데이터베이스 파일과 로그는 소유자만 읽을 수 있도록 권한을 좁혀 저장합니다.

처음 실행할 때 묻는 statusline 연결에 동의한 경우에는 같은 폴더의 statusline/ 아래에 사용량 스냅샷과 원래 statusline 설정 백업을 소유자만 읽을 수 있게 저장합니다. 이 파일들도 사용자 컴퓨터 밖으로 보내지 않습니다.

자료 드로어에 올린 파일과 링크 수집으로 가져온 페이지 본문도 같은 폴더 아래 자료 폴더에만 저장합니다. MCP로 가져온 본문도 마찬가지입니다. 연결 모듈의 CLAUDE.md·AGENTS.md·README.md는 질문이나 [자료] 실행, 자료 대화를 시작할 때마다 같은 폴더의 linked-docs/ 아래로 사본을 만들어 claude가 읽게 합니다. 이 사본은 다른 프로젝트 문서의 복사본이라 앱 데이터에 남고, 다음 실행에서 덮어씁니다. 연결 모듈 사이의 관계와 역할은 데이터베이스에 저장합니다. 이 내용도 사용자 컴퓨터 밖으로 보내지 않습니다.

외부 연계로 가져온 일감 제안(제목·본문·작성자·라벨·원본 주소)은 같은 데이터베이스에만 저장합니다. 연계 설정은 같은 폴더의 connectors/에 파일로 두고, 소스를 삭제하면 그 파일과 그 소스에서 가져온 제안을 함께 지웁니다. 원본이 닫혔거나 무시한 제안은 30일, 승인한 제안 중 회신이 끝났거나 회신할 것이 없는 제안은 90일이 지나면 제목·본문·작성자·라벨·원본 주소·작업 경로·결과 요약을 지웁니다. 같은 일감이 다시 제안되지 않도록 소스 이름, 연결 이름(GitHub 은 owner/repo), 원본 일감 번호, 제안·회신 상태, 처리 시각만 흔적으로 남기며, 흔적은 화면에 보이지 않습니다. 승인한 작업이 아직 대기·실행 중이면 지우지 않습니다(켠 소스가 하나 이상 있을 때 정리합니다).

사용량 스냅샷에는 Claude Code가 statusline에 넘기는 입력 JSON이 통째로 저장됩니다. 여기에는 작업 폴더 경로(cwd), 세션 ID, 대화 기록 파일 경로(transcript_path), 모델 이름이 들어 있을 수 있습니다. CmdQ는 그중 사용량 한도(rate_limits) 값만 읽습니다.

네트워크 통신

CmdQ가 직접 보내는 요청은 업데이트 확인과 사용자가 자료나 첨부로 넣은 링크를 앱 안 웹뷰로 여는 요청(아래 「웹뷰 수집과 로그인」)입니다. 여기에 더해 사용자가 연계를 켠 소스에 한해 외부 일감 서비스로 요청을 보냅니다(아래 「외부 연계(선택 기능)」).

요청 대상
github.com (릴리스 정보)
보내는 내용
없음 — 파일을 내려받기만 합니다
목적
새 버전 존재 여부 확인
업데이트 확인 요청에는 사용자를 식별할 수 있는 정보가 담기지 않습니다. 공개된 릴리스 정보 파일을 내려받아 현재 버전과 비교할 뿐이며, 사용 기록이나 작업 내용은 포함되지 않습니다. 내려받은 업데이트는 서명을 검증한 뒤에만 설치합니다.

그 밖에 사용자가 실행한 Claude Code CLI 명령이 발생시키는 통신은 공식 CLI가 수행하는 것이며 CmdQ의 통신이 아닙니다.

외부 연계(선택 기능)

외부 연계는 GitHub 이슈나 Todoist 작업을 가져와 받은 일감에 제안으로 보여 주는 기능입니다. 소스마다 처음에는 꺼져 있고, 사용자가 소스를 켰을 때만 주기적으로 조회합니다. 그 밖에는 사용자가 연결 추가를 쓸 때만 동작합니다. MCP 서버 목록을 보면 Claude Code 설정을 읽고, 저장 전 샘플을 조회하면 같은 조회 요청을 한 번 보냅니다. 켠 소스가 없고 연결 추가도 쓰지 않으면 연계 때문에 생기는 네트워크 요청, gh·MCP 서버 실행, 키체인 접근이 없습니다. 지원하는 소스는 GitHub(gh CLI), Todoist(API), GitHub MCP 프리셋입니다.

MCP (GitHub MCP 프리셋)

요청 대상
사용자가 Claude Code에 등록한 MCP 서버. 로컬(stdio) 서버는 CmdQ가 직접 실행하고, 원격 서버는 https 공개 주소에만 CmdQ가 직접 연결합니다
보내는 내용
연계 정의에 적힌 읽기 도구 호출(기본은 내가 쓴 열린 이슈만). 작업이 성공하면 정의에 적힌 댓글 도구로 결과 요약(닫기 방식이면 요약 댓글 뒤 닫기 도구 호출). 작업이 실패하면 실패해도 댓글로 알림을 켠 소스에만 댓글 도구로 고정 실패 문구(작업 결과 내용은 보내지 않음)를 보냄(닫지 않음)
시작 조건
소스 설정에서 이 소스를 켰을 때만
자격 저장 위치
Claude Code 설정 ~/.claude.json의 사용자 범위(mcpServers)와 연결 폴더의 로컬 범위(projects.<경로>.mcpServers). CmdQ는 읽기만 하고 저장하지 않습니다. 프로젝트의 .mcp.json은 읽지 않습니다
MCP 소스는 조회·회신할 때마다 ~/.claude.json의 사용자·로컬 범위에서만 서버 실행 정보를 읽습니다. 원격 서버는 설정에 고정 헤더(headers)가 있을 때만 연결하며, 그 헤더 값(토큰 포함)은 메모리에서만 쓰고 데이터베이스·연계 설정 파일·로그에 저장하지 않습니다. 헤더가 없는 원격 서버(OAuth 등)는 연결하지 않고 인증 실패로 표시합니다. 브라우저 로그인을 띄우거나 Claude Code의 OAuth 인증 정보를 읽지 않습니다.

결과 회신은 공개 저장소에 올라갈 수 있으므로 길이를 1,000자로 자르고 로컬 경로·토큰 모양의 문자열·환경 변수 값을 지운 요약만 보냅니다. 실패한 작업은 실패해도 댓글로 알림을 켠 소스에만 고정 실패 문구 「작업이 실패했습니다.」(작업 결과 내용은 보내지 않음) 댓글을 남기고 닫지 않습니다. 실패 댓글은 원본 일감 하나에 한 번만 남깁니다. 회신하기 직전에 그 소스가 꺼져 있거나 Pro 미리보기가 끝났으면 보내지 않습니다. 가져온 일감은 사용자가 승인하기 전에는 실행되지 않습니다. Todoist·원격 MCP 연결은 환경 변수의 프록시(HTTPS_PROXY 등)도 쓰지 않고 항상 직접 연결합니다. GitHub 연결을 제안하려고 열린 프로젝트 폴더의 git remote -v를 읽기만 하며, 주소 원문은 저장하지 않고 github.com의 저장소 이름만 씁니다.

MCP 수집(선택 기능)

링크 수집에서 MCP를 고르면(지금은 GitHub 주소만 지원합니다) 그때만 시작합니다. CmdQ는 페이지 하나를 가져올 때마다 수집 전용 claude -p를 띄우고 그 서버의 읽기 도구 하나만 허용합니다. 사용자가 Claude Code에 등록한 MCP 서버가 외부에 요청을 보내는 것이며, CmdQ가 직접 보내는 요청이 아닙니다. 위의 「공식 CLI가 수행하는 통신」과 같은 경계입니다.

시작 조건
사용자가 수집 방법에서 MCP를 고르고 수집 시작을 눌렀을 때만
CmdQ가 하는 일
claude mcp list로 서버 이름과 상태를 읽고, 수집 전용 claude -p를 페이지마다 실행
가져온 본문
자료 폴더에만 저장 (원본 주소·가져온 방법을 적은 머리말 포함)
한도
용량 500MB, 주소 5,000개(웹뷰 수집과 같음), 깊이 기본 3(시작할 때 1~10)
MCP 수집에서 앱은 MCP 토큰, 인증 정보, MCP 설정 파일을 읽지도 저장하지도 않습니다. MCP 서버 목록은 claude mcp list가 출력하는 서버 이름과 상태로만 압니다. 인증은 Claude Code와 MCP 서버가 처리합니다. 설정 파일을 읽는 것은 위 「외부 연계」의 MCP 소스뿐이고, 그 소스를 켠 경우에만 읽습니다.

수집 전용 claude -p는 사용자의 훅과 CLAUDE.md를 불러옵니다. 훅과 CLAUDE.md를 끄는 옵션이 MCP도 함께 끄기 때문입니다. 이를 줄이려고 저장소 밖 빈 작업 폴더에서 실행하고, 모델의 답이 아니라 도구가 돌려준 원문만 저장합니다. 페이지마다 claude를 한 번 실행하므로 페이지 수만큼 실행 비용과 시간이 듭니다. 요약 실행은 계속 사용자 MCP를 쓰지 못하게 막습니다. 자료 질문 대화도 기본으로 막고, 대화에서 MCP 도 함께 묻기를 켠 경우에만 그 서비스(지금은 GitHub)의 읽기 도구를 씁니다.

웹뷰 수집과 로그인

웹뷰로 수집하다 로그인 화면으로 넘어가면 수집을 멈춥니다. 사용자가 같은 웹뷰에서 직접 로그인한 뒤 이어 받기를 누르면 멈춘 페이지부터 다시 받습니다. CmdQ는 비밀번호나 쿠키를 읽거나 저장하지 않습니다.

인증 정보

CmdQ는 다음을 수행하지 않습니다.

  • Claude·Anthropic의 OAuth 토큰 또는 API 키 읽기
  • Claude·Anthropic 인증 정보 저장 또는 전송
  • 로컬에 저장된 Claude Code 인증 정보 접근
  • MCP 토큰·인증 정보·MCP 설정 파일(~/.claude.json의 mcpServers, .mcp.json 등)의 값 저장. MCP 수집에서는 읽지도 않습니다
  • 웹뷰에 입력한 비밀번호·쿠키 읽기와 저장

Claude 인증은 모두 Claude Code CLI가 관리합니다.

사용자가 외부 연계를 켠 경우에만 예외가 있습니다(위 「외부 연계(선택 기능)」). Todoist 같은 API 연계의 토큰은 사용자가 입력한 값을 macOS 키체인의 CmdQ 항목에만 저장하고, 조회·회신할 때 그 연계의 주소로만 보냅니다. GitHub(gh)는 gh 자체 로그인을 그대로 씁니다. MCP 소스는 Claude Code 설정의 서버 실행 정보와 원격 서버 헤더(토큰 포함)를 읽기만 하고 저장하지 않습니다.

사용량 조회에는 OAuth 토큰, claude.ai 쿠키, macOS 키체인을 쓰지 않습니다. 대신 Claude Code statusline이 넘겨주는 값을, 처음 실행할 때 묻는 statusline 연결에 동의했을 때만 읽습니다.

기술적 근거

이 방침은 다음 확인에 기반합니다.

  • Claude·Anthropic 인증 정보를 다루는 코드 없음 — api_key·ANTHROPIC 관련 코드가 존재하지 않습니다. 토큰을 다루는 코드는 외부 연계의 키체인 저장·읽기와 MCP 원격 서버 헤더 전달뿐입니다
  • 업데이터의 요청 대상은 위에 명시한 릴리스 정보 파일입니다. 앱 코드가 보내는 그 밖의 HTTP 요청은 사용자가 켠 외부 연계에서만 나가고, https 공개 주소만 허용합니다(사설·루프백 주소는 거부). MCP 수집은 앱이 요청을 보내는 것이 아니라 claude 프로세스를 실행하는 방식입니다
  • 분석·추적 도구를 포함하지 않습니다
